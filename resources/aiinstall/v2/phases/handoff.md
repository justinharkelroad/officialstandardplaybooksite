# Session handoff

Outcome: a bridge between conversations. The handoff is not the memory system. The files are. Create a handoff when a session is ending, the conversation is getting long, or the owner is moving from one phase to the next.

## What to do

1. Read the workspace. If `SESSION-HANDOFF.md` already exists, you are updating it. Keep one standard file name.
2. Summarize only verified information under these headings:
   1. Purpose of the brain
   2. Work completed in this session
   3. Files and folder structure created or changed
   4. Business context learned
   5. Active projects, owners, numbers, blockers, and next milestones
   6. Memory-system structure and master file name
   7. Decisions made
   8. Instructions and operating rules
   9. Skills, morning brief, dashboard, and upkeep: what exists and what was tested
   10. Tests run and what passed or failed
   11. Incomplete work
   12. Exact current state
   13. Where the next conversation should resume
3. Write `Not started` under any heading that does not apply yet.
4. For every completed phase, name the file that proves completion.
5. Clearly separate facts from assumptions and missing information.
6. Do not claim that a report skill works on the owner's carrier data unless a known sample reconciled.
7. Show the handoff for review. Save after approval.
8. End the file with this line: `Wait for the next phase command before beginning additional phase work.`

## Pass condition

- `SESSION-HANDOFF.md` exists and names the owner's actual files.
- It separates completed, incomplete, and untested work.
- It names the exact next step.
