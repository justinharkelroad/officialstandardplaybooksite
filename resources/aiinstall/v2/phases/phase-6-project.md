# Phase 6. Active project

Outcome: the brain stops being a biography and starts carrying current work. Run this command once for each project. A project is not a topic. It has a real outcome, an owner, one useful number, a deadline or decision window, a blocker, and a dated next milestone.

## What to do

1. Ask which project this file is for. If the owner does not know which projects deserve files, read `about-me.md`, `working-preferences.md`, and `team-members.md`, then ask one question at a time to find the two or three projects creating the most operating friction, financial exposure, missed follow-up, or team confusion. Recommend the smallest set. Do not choose the owner's priorities for them, and do not create any file until they approve the list.
2. Read `current-projects/_project-template.md` for the shape.
3. Interview the owner one question at a time. The owner may be speaking. Force clarity on:
   1. The specific result that would make this project complete.
   2. Why it matters now.
   3. The one number that best shows movement.
   4. The current value, target value, source, and reporting period for that number.
   5. Who owns the next move.
   6. The deadline and what created it.
   7. The next decision that only the owner can make.
   8. The current blocker.
   9. The earliest visible sign that the project is off pace.
   10. The exact next milestone and its date.
4. For the one number: if AgencyBrain is connected and can supply it, ask the owner before reading it, then record the value with its source and the date you read it. If the value is unknown, write `Current value: Missing` and name the source needed to establish it. Never invent a current number or a target.
5. If the owner cannot choose the number: ask what decision this project is meant to improve and what evidence can be measured consistently. Offer no more than three candidate measures, explain the tradeoff in plain language, recommend one, and wait for their choice. Do not pick a vanity metric for them.
6. Write the file in `current-projects/` with these sections: what it is and why it matters; the one number; current status; milestones and deadlines; who is involved; open decisions; blockers. End the file with `Next milestone:` on its own line.
7. Show the file and ask what to correct. Save after approval.

## If the project needs a report

Keep the raw report outside `MY BIZ BRAIN`. Ask for its local path and the one approved question. Show the source period, definitions, exclusions, missing fields, and calculations. Write only the approved findings and the next action into the project file.

## Test

Review every file in `current-projects/` except the template. Give a short project review with: project, owner, current status, one number, next milestone, deadline, blocker, and open decision. Do not invent missing fields. Flag incomplete files.

## Pass condition

- The project file exists in `current-projects/`.
- It states a real outcome and an owner.
- It names one useful number and its source.
- Unknown values are labeled `Missing`.
- It has a deadline, a blocker, and a dated next milestone.
- The project review names no unsupported facts.
